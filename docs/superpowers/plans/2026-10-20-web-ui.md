# os-config 本地 Web UI 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为 `os-config` 增加一个仅监听 `127.0.0.1` 的本地 Web UI：选择/编辑工具清单与参数，点击一次即可在当前机器执行 `setup.sh`，并实时显示逐行日志与每个工具的安装/校验结果。

**Architecture:** Web UI 只是 `setup.sh` 的前端外壳，不复制任何安装逻辑。Python 3.10 标准库 HTTP 服务负责鉴权、参数校验、`ui.env` 写入、子进程编排与 SSE 推送；Bash 引擎新增结构化 JSONL 事件（`OS_CONFIG_EVENTS`）供 UI 精确判断单项状态，前端为无构建步骤的原生 HTML/CSS/JS。

**Tech Stack:** Bash 4+、Python 3.10 标准库（`http.server`、`subprocess`、`secrets`、`json`、`unittest`）、原生 HTML/CSS/JS（`EventSource`）。

**Spec:** `docs/superpowers/specs/2026-10-20-web-ui-design.md`

## Global Constraints

- 只监听 `127.0.0.1`，默认端口 `8765`；不引入任何 Python 第三方依赖。
- 前端为原生 HTML/CSS/JS，无构建步骤、无 CDN 依赖。
- 所有安装/校验/卸载操作必须通过 `setup.sh` 子进程完成，UI 不直接改系统。
- 随机 token 鉴权，比较使用 `secrets.compare_digest`；token 不写入日志、不进入进程参数。
- 参数只允许 spec D5 白名单中的键；只写用户触碰过的键；写 `config/ui.env` 必须原子写入且权限 0600；密码类值永不回显。
- `/api/plan` 不得写 `ui.env`，不得执行写操作。
- 所有 `POST` 必须校验 `Content-Type: application/json`，否则返回 415；JSON 解析失败返回 400。
- 卸载（`remove`）必须显式进入卸载区并二次确认；取消勾选 ≠ 卸载。
- Bash 保持 `set -uo pipefail`、不加 `set -e`；事件写入失败不得影响安装流程。
- UI 默认 `--yes`（非交互）、默认 `--keep-going`（可在界面关闭）、默认安装后 `verify`（可关闭）。
- 提交纪律：仅在人类伙伴明确授权提交时执行各任务的提交步骤；未授权则跳过提交、保留工作区改动。

```bash
_exit_report() {
  local rc=$?
  rollback_on_exit "$rc"
  events_emit run_end "\"verb\":\"$(json_escape "$VERB")\",\"phase\":\"$(json_escape "$VERB")\",\"ok\":${ENGINE_OK:-0},\"skipped\":${ENGINE_SKIPPED:-0},\"failed\":${ENGINE_FAILED:-0},\"rc\":$rc,\"rolled_back\":$([[ "${_ROLLBACK_PERFORMED:-0}" == 1 ]] && echo true || echo false)"
  exit "$rc"
}
trap '_exit_report' EXIT
```

  - `apply_param_changes(existing: dict[str,str], params: dict[str,str], reset_keys: list[str]) -> dict[str,str]`（三态：未出现=继承，`""`=显式空，值=覆盖；未触碰的已有键保留）。

### Task 7: 计划、运行、SSE 与锁

**Files:**
- Modify: `ui/server.py`
- Test: `tests/test_ui_server.py`

**Interfaces:**
- Consumes: `AppConfig`、`schema`、`events` 协议。
- Produces:
  - `POST /api/plan` body `{"verb":"install","pick":["git"]}` → `{"items":[{"id","type","selected","required_by","status","rc"}],"logs":[...],"exit":int}`。`selected` 表示该 id 在请求的 pick 中；`required_by` 是由 catalog `deps` 直接指向该 id 的已选 id 列表（依赖自动加入但来源可见）。内部执行 `setup.sh <verb> --dry-run --pick <tokens> --yes`，不写 `ui.env`；非法 pick/verb → 400。
  - `POST /api/run` body：
    ```json
    {"verb":"install","pick":["git"],"params":{"GIT_USER_NAME":"A"},"reset_params":[],
     "keep_going":true,"verify_after":true,"dry_run":false,"force":false,"confirm":false}
    ```
    返回 `202 {"run_id":"YYYYMMDD-HHMMSS-<6hex>"}`；并发运行 409；`verb` 仅 `install|remove|verify`（D2，`update` → 400）；`remove` 且 `confirm != true` → 400；非 JSON Content-Type → 415。
  - `GET /api/events`（SSE）：事件名 `log|plan|item|rollback|summary|done`，`data` 为 JSON；`protocol_version = "HTTP/1.1"` 并 flush；每个事件带 `id: N`，支持 `Last-Event-ID` / `?after=N` 从环形缓冲（2000 条）回放；**缺省两者时从头回放整个环形缓冲**，使页面重新打开后仍能看到正在运行任务的日志；15s 心跳注释；每客户端 `queue.Queue(maxsize=1000)`，`BrokenPipeError` 静默退出。
  - `GET /api/history/<run_id>` → `{"run_id","meta","events":[...],"log":"<最多 1 MiB>"}`；只接受 `safe_run_id` 形状的名字，非法 400，不存在 404。
  - `RunJob`：写 `ui.env` 与 `selection.json`、启动子进程、逐行读 stdout/stderr、tail 事件文件、安装成功后可选 `verify` 阶段、写 `state/ui/runs/<run_id>/{meta.json,run.log,events.jsonl}`、释放锁。
    - `selection.json` 结构：`{"version":1,"tools":[...],"adhoc":[原始 token...],"verb":"install","updated":"<UTC ISO8601>"}`；写失败也在 `finally` 中尝试落盘；原子 `os.replace`、0600。
    - 子进程环境 `env = os.environ | {"OS_CONFIG_EVENTS": events_path, "ASSUME_YES": "1"}`；参数 `--pick` 加每个原始 token、`--yes`，并按需加 `--keep-going`/`--force`/`--dry-run`。
    - 日志：剥 ANSI、去尾换行，写 `run.log`（0600）与内存环形缓冲，并推送 `log`。
    - 事件 tail 每 0.1s 轮询增长，只处理完整行；`item_*` 推 `item`，`rollback` 推 `rollback`，`run_end` 暂存；收到 `run_start` 时额外推送合成 `plan` 事件（含 `ids`）。
    - verify 阶段仅当 `verify_after`、安装 `rc == 0` 且 `rolled_back == false` 时执行；`remove` 之后永不 verify。
    - `meta.json`：`{run_id, verb, pick, started, finished, rc, rolled_back, ok, skipped, failed, verify_rc}`；结束时推 `summary` 与 `done`，锁在 `finally` 释放。
  - 锁：`state/ui/run.lock`（`O_CREAT|O_EXCL`，内容 pid）+ 进程内 `threading.Lock`；必须在返回 202 之前同步获取；陈旧锁（pid 不存在）自动清理。
